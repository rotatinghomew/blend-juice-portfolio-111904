# 果汁试榨与混配

试榨、测量与原料用量为虚构数据。百分比保留原始单位。

`data` 保存原始记录，`DATA.md` 是资料字典。`blendplan` 是只读的混配前分析：
把试榨证据、袋级读数、用量账和槽位限制连起来，给出「哪些原料组合撑得起
订单、哪些只能暂估、新称重时需要改哪几张工单」。

环境使用 Python 3.11.2。安装锁定的依赖并检查资料：

```sh
python3 -m pip install -r requirements.txt
python3 -m unittest discover -s tests -v
```

检查只读取本地数据，不访问业务系统。

## 生成分析

```sh
# 11-10 上午，接单前
python3 -m blendplan --as-of 2026-11-10T09:00:00+08:00

# 11-11 投料与过磅修正后，对比上一快照，列出要改的工单
python3 -m blendplan --as-of 2026-11-11T08:30:00+08:00 \
    --previous 2026-11-10T09:00:00+08:00

# 某槽当天已关闭、不能再排产（可选，可重复）
python3 -m blendplan --as-of 2026-11-11T07:30:00+08:00 --closed-slot S1
```

输出为 Markdown：原料卡、可承诺方案、条件接单方案、班次槽位、承诺影响、
用量账、产出校正、历史试榨复核、配方/价差口径、改单清单、补证清单。

## 口径（与 `DATA.md` 对应）

| 主题 | 处理 |
|---|---|
| 袋与整车 | 读数按 `prep`（袋）聚合；同袋 `replicate` 不是独立整车观测 |
| 复测版本 | 同一袋的新 `version` 替换旧值，只算一袋；部分复测会缩减可靠性 |
| 时点 | 一切按 `known_at`/`started_at` 取快照；开工后才知的成品不回填开工前证据 |
| 过磅修订 | `raw.rev` 只有 `known_at` 之后可见；旧重量在新快照里不再适用 |
| 出汁与损耗 | `usable_juice_kg` 与 `loss_kg` 分开；损耗不计入出汁率 |
| 糖酸关系 | 成品酸度由成品糖度决定（`acid_out = c0 + c1*brix_out`），不独立优化 |
| 情景 | 低/高情景由同一袋的糖酸重建，不跨样本拼接最优值 |
| 锁料/投料 | 锁料是计划，只有 `已投料` 扣减可用量；已投料不可回退 |
| 成品入库 | 单列，用于校正出汁率与解释剩料，不冲减投料、不取消锁料 |
| 整批 | `splittable=0` 的批整批进一单，不分拆 |
| 槽位 | 一槽一单；容量含该槽已投料；换档需 `cleanup_allowed` |
| 到期 | 批次不能进入 `expires` 当天或之后的槽 |
| 已锁窗口 | `锁料`/`已投料` 绑定的槽不自动后移；已产出的槽不再排产 |
| 覆盖 | 只有试榨覆盖内的批次可承诺；外推/新来料只能条件接单 |

## 代码结构

```
blendplan/
  data.py       读取、as-of 快照、袋级证据与整车质量
  estimates.py  试榨模型（出汁率、成品糖度、成品酸度、酸-糖线）与覆盖范围
  ledger.py     用量账（锁料/待批/已投料）与产出账（成品入库）
  planner.py    槽位分配 + 混配 MIP（容量、到期、整批、质量窗口、情景复核）
  report.py     面向主管的报告数据（承诺影响、产出校正、历史复核、补证）
  render.py     Markdown 输出
  __main__.py   命令行
tests/
  test_source_contract.py  原始 CSV 结构与主键
  test_blendplan.py        业务不变量
```
